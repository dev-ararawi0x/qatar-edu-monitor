Phase 3

LMS connection security and fake adapter

Credential material is encrypted with AES-256-GCM, bound to the owning user/connection through AAD, never returned by the API, and wiped on revoke. The LMS integration boundary remains a fixture-backed fake because live authorization gates are unresolved.

Encryption: random 12-byte nonces, GCM authentication tags, key versioning, and AAD binding make tampering or cross-owner ciphertext reuse fail closed.

Persistence: one connection per user; encrypted fields obey an all-present/all-null database check. Revocation sets them null in the same update.

Boundary: routes parse Zod contracts, resolve the Better Auth actor, call application use cases, and return sanitized errors.

Fake LMS: success, expired, blocked, timeout, and parser mismatch outcomes are deterministic test modes; unknown HTML throws PARSER_MISMATCH.
